# Tasks：個人・チーム統合タスク管理アプリ（Phase 1）

個人タスクと 1 つのチームの共同タスクを、ひとつの画面でまとめて管理する Web アプリです。
React + TypeScript + Vite + Tailwind CSS + Supabase（PostgreSQL / Auth / RLS）で作っています。

---

## 1. 画面構成

| 画面 | パス | 内容 |
| --- | --- | --- |
| ホーム | `/` | 今日の日付、今日の個人タスク・チーム担当タスク、今日期限・3日以内・期限超過・前日からの未完了、今日/今月の完了率、クイック追加・完了 |
| 個人タスク | `/personal` | 本人だけのタスク。期間タブ（今日/今週/今月/すべて/期限超過/完了済み）、検索・並べ替え・絞り込み、カテゴリー、リスト⇔カンバン |
| チームタスク | `/team` | チームで共有するタスク。担当者・プロジェクトでの絞り込み、進捗率、メンバー別進捗、リスト⇔カンバン |
| カレンダー | `/calendar` | 月間・週間表示、自分/個人/チーム全体の切り替え、完了の表示切り替え、日付を選んでタスク確認・追加 |
| マンスリー | `/monthly` | 月の切り替え、月間達成率、月間目標、今月期限のタスク、対象月だけのタスク、翌月への繰り越し |
| プロジェクト | `/projects` | プロジェクト一覧と進捗率。作成・編集は管理者のみ |
| 通知センター | `/notifications`（右上のベル） | 期限3日以内・今日期限・期限超過・自分への割り当て |
| チーム・設定 | `/settings` | チーム作成・参加、メンバー管理、招待リンク、表示名、カテゴリー、ライト/ダーク |
| 招待参加 | `/join/:token` | 招待リンクからチームに参加 |

PC では左にサイドバー、右上に通知ベルと「タスクを追加」ボタンがあります。
スマートフォンでは画面下にナビゲーション、右下にワンタップで使える追加ボタンがあります。

## 2. 技術構成

```
ブラウザ（React SPA） ──HTTPS──▶ Supabase
  ・anon キーのみ使用          ├─ Auth（メール＋パスワード）
  ・表示の制御だけ担当         ├─ PostgREST（テーブル / RPC 関数）
                               └─ PostgreSQL（RLS とトリガーで権限を強制）
```

* **権限はすべてデータベースで判定します。** 画面でボタンを無効にしているのは見た目のためだけです。
  ブラウザを改造して API を直接呼んでも、RLS とトリガーで拒否されます。
* service_role（secret）キーはどこにも使っていません。ブラウザに入れないでください。

## 3. データ設計

`supabase/migrations/20261025000000_phase1_schema.sql` にすべてあります（コメント付き）。

| テーブル | 役割 |
| --- | --- |
| `profiles` | 表示名・メール（auth.users と 1:1、登録時に自動作成） |
| `teams` | チーム（ユニークインデックスで **1 行だけ** に制限） |
| `team_members` | 所属と権限（`admin` / `member`）。1 ユーザー 1 チーム |
| `team_invites` | 招待リンク（トークンは **SHA-256 ハッシュのみ保存**、期限・回数上限・取り消し） |
| `invite_attempts` | 招待コードの失敗記録（総当たり対策。ブラウザからはアクセス不可） |
| `projects` | チームのプロジェクト |
| `categories` | 個人タスクのカテゴリー（本人のみ） |
| `tasks` | 個人・チーム両方のタスク（`scope` 列で区別） |
| `notifications` | アプリ内通知（`(user_id, task_id, kind)` がユニーク＝重複しない） |
| `monthly_goals` | 月間目標（本人のみ） |

### tasks の主な列

| 列 | 内容 |
| --- | --- |
| `id`, `title`, `scope`（personal/team）, `created_by`, `status`, `created_at`, `updated_at` | 必須項目 |
| `description`, `assignee_id`, `project_id`, `category_id`, `priority`（high/medium/low） | 任意 |
| `scheduled_date`（実施予定日）, `due_date`（締切日）, `due_time`（締切時刻） | 予定日と締切日は別の列。**1 つのタスクが両方を持つので重複保存されません** |
| `target_month` | 「11月中に実施」のような対象月（その月の 1 日で保存） |
| `completed_at` | 完了にすると DB が自動で記録、戻すと消去 |
| `recurrence`, `recurrence_days` | 繰り返し（毎日/毎週/毎月/曜日指定） |

日付は日本時間（Asia/Tokyo）で判定します。日付だけの締切はその日の 23:59 まで有効です。

### 権限ルール（RLS + トリガー）

| 操作 | 管理者 | 一般メンバー | チーム外 |
| --- | --- | --- | --- |
| 個人タスク | 自分の分だけ | 自分の分だけ | 自分の分だけ |
| チームタスクの閲覧 | ○ | ○ | × |
| チームタスクの作成 | ○（誰にでも割り当て可） | ○（担当は「なし」か「自分」） | × |
| ステータス変更 | 全タスク | 自分が担当・作成したタスク | × |
| タイトル・期限などの編集 | 全タスク | 自分が作成したタスク | × |
| 担当者の変更 | ○ | 「未割り当て⇔自分」のみ | × |
| 削除 | 全タスク | 自分が作成したタスク | × |
| プロジェクト作成・編集 | ○ | × | × |
| 招待・権限変更・メンバー削除 | ○（最後の管理者は降格できない） | 自分の退出のみ | × |

* RLS の循環参照を避けるため、「メンバーか」「管理者か」の判定は `SECURITY DEFINER` 関数
  （`is_team_member` / `is_team_admin`）で行っています。
* `team_members` にはブラウザから直接書き込めません。参加は `accept_invite`、権限変更は `set_member_role` 関数だけで行えます。
  そのため一般メンバーが自分を管理者にすることはできません。
* 列ごとの制限（担当者だけならステータスのみ変更可、など）は `tasks_guard` トリガーで、**更新時にも** 検証しています。

### 通知の仕組み（重複防止）

* 担当者が設定されると、トリガーが「割り当て」通知を 1 件作ります。
* アプリを開いたとき・データを更新したとき・5 分ごとに `refresh_notifications()` を呼び、
  期限系の通知を「今あるべき状態」に同期します。1 タスクにつき期限系通知は最大 1 件で、
  「3日以内 → 今日 → 期限超過」と置き換わります。完了したタスクの通知は消えます。

### 繰り返しタスク

完了にすると、DB トリガーが次回分のタスクを 1 件だけ作ります（完了を付け直しても重複しません）。
1 回分を完了しても未来の予定はなくなりません。

## 5. ローカルでの起動方法

### 必要なもの
* Node.js 20 以上
* Docker Desktop（ローカルで Supabase を動かす場合）

### 手順

```bash
cd taskapp
npm install

# ① ローカル Supabase を起動（初回は Docker イメージのダウンロードで数分かかります）
npm run db:start
#   → 表示される "API URL" と "anon key"（Publishable key）を控える
#   → マイグレーション（テーブル・RLS）は自動で適用されます

# ② 接続情報を設定
cp .env.example .env.local
#   .env.local の VITE_SUPABASE_URL と VITE_SUPABASE_ANON_KEY を書き換える
#   （anon キーは `npx supabase status` でも確認できます）

# ③ アプリを起動
npm run dev
#   → http://localhost:5173 を開く
```

ローカル Supabase では、新規登録時のメール確認は無効です（`supabase/config.toml` の `enable_confirmations = false`）。

DB を初期状態に戻すには `npm run db:reset`、止めるには `npm run db:stop` を実行します。

### クラウドの Supabase を使う場合（無料プラン）

1. https://supabase.com でプロジェクトを作る（リージョンは Tokyo がおすすめ）
2. ダッシュボードの **SQL Editor** で `supabase/migrations/20261025000000_phase1_schema.sql` の中身を貼り付けて実行する
3. **Project Settings → API** の Project URL と anon（publishable）key を `.env.local` に書く
4. **Authentication → URL Configuration** の Site URL に公開先の URL（例：`https://xxxx.pages.dev`）を設定し、
   Redirect URLs に `http://localhost:5173` も追加する
5. メール確認を有効にしたまま使う場合、新規登録後に届くメールのリンクを開いてからログインします

### 公開（無料ホスティング）

Cloudflare Pages / Vercel / Netlify のどれでも動きます。

* ルートディレクトリ：`taskapp`
* ビルドコマンド：`npm run build`
* 出力ディレクトリ：`dist`
* 環境変数：`VITE_SUPABASE_URL`、`VITE_SUPABASE_ANON_KEY`

`/team` などの URL を直接開いても動くように、`public/_redirects`（Cloudflare/Netlify 用）と `vercel.json` を入れてあります。

## 6. 2 アカウントでのチーム共有テスト

### 自動テスト（DB の権限）

```bash
npm run db:reset     # チームは 1 つだけなので、空の DB で実行します
npm run test:share
```

ブラウザと同じ anon キーで、管理者 A・メンバー B・部外者 C の 3 アカウントを作って 44 項目を確認します
（共有、個人タスクの非公開、権限の昇格防止、招待の期限・回数上限・総当たり対策、通知の重複防止、繰り返し など）。

### 手動テスト（画面）

ブラウザを 2 つ（通常ウィンドウとシークレットウィンドウなど）用意してください。

1. **A**：新規登録 → 「チーム・設定」でチームを作成（A が管理者になる）
2. **A**：「招待リンクを発行」→ リンクをコピー
3. **B**：もう一方のブラウザでリンクを開く → 新規登録 → 「チームに参加する」
4. **A**：個人タスクを 1 件追加。チームタスクを「担当者 = B」「締切 = 今日」で追加
5. **B**：再読み込み（右上の ⟳ ボタン）→ チームタスクが見え、A の個人タスクは見えないこと。ベルにバッジが出ること
6. **B**：カンバン表示でカードを「進行中」へドラッグ
7. **A**：再読み込み → 「進行中」になっていること
8. **B**：タスクを開き、タイトルなどが編集できず、ステータスだけ変更できること
9. **A**：「チーム・設定」で B を管理者にする／外す、招待リンクを取り消す、などを試す

## 7. Supabase 無料プランの主な制限

（2026 年時点の目安です。最新の内容は Supabase の料金ページを確認してください）

* **一定期間アクセスがないとプロジェクトが一時停止**します（目安は 1 週間）。ダッシュボードから再開できます
* データベース容量は 500MB 程度。小さなチームのタスク管理なら十分です
* 無料プランで作れるプロジェクトは 2 つまで
* 標準のメール送信（確認メールなど）は 1 時間あたりの送信数がかなり少ないです。
  人数が増えたら独自の SMTP を設定するか、メール確認をオフにしてください
* 自動バックアップはありません。大事なデータは定期的にエクスポートしてください
* Cloudflare Pages / Vercel / Netlify の無料プランでも、このアプリの公開には十分です

### 既知の問題・注意点
* 他のメンバーの変更は自動では表示されません。⟳ ボタン、再読み込み、タブへの切り替え時に取り込みます
* 2 人が同時に同じタスクを編集すると、後から保存した方の内容になります
* 繰り返しタスクは「完了したら次を作る」方式です。未完了のまま期限が過ぎても、次回分は作られません
* 一般メンバーは、他の人が作成した「未割り当て」のタスクを自分で引き受けられません（自分担当を外した場合も同じです）。担当の割り当ては管理者に依頼してください
* 全タスクを一度に読み込む作りのため、数万件規模になると表示が遅くなります（小規模チーム向け）
* カレンダーには締切日（なければ予定日）の 1 か所にだけ表示します
